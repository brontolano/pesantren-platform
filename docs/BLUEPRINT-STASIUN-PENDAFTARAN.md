# Blueprint — Stasiun Pendaftaran Santri (2026-06-11)

Riset 4-arah (capture hardware, handwriting AI, auto-NIS/UX stasiun, audit repo).

## Visi

Stasiun Pendaftaran Santri adalah satu halaman loket Filament (replikasi pola LoketKas yang sudah terbukti) tempat santri dipanggil satu per satu: petugas mencari NIS atau sistem menerbitkan NIS baru otomatis sesuai format custom pesantren, lalu menjalankan checklist 7 langkah non-blokir â€” foto webcam, tanda tangan canvas, sampel tulisan Arab & Indonesia ber-QR, tautan kartu NFC, PIN + QR, dan cetak kartu â€” meniru ritme perekaman e-KTP Dukcapil (verifikasi dulu, urutan tetap, status eksplisit per tahap). Prinsip utamanya: KUMPULKAN DATA SEKARANG, MODEL AI MENYUSUL â€” momen enrollment massal tidak terulang, sehingga foto, tanda tangan, dan sampel tulisan berlabel + ground-truth otomatis (teks formulir diketahui) adalah aset yang pasti dibutuhkan apa pun model AI-nya nanti. Hampir semua fondasi sudah ada di repo: IdCardService (QR chillerlan), SantriAccountService (PIN), pola counter race-safe SuratService untuk auto-NIS, route /_tenant-storage untuk file, dan infra pgvector+Ollama+worker-ai untuk fase AI kelak. Dua ekspektasi yang dikoreksi dari permintaan awal: sidik jari di tablet loket bersama TIDAK mungkin dengan WebAuthn (kredensial terikat perangkat; yang realistis adalah passkey di HP pribadi santri/wali), dan scanner fingerprint USB ditunda karena butuh agent desktop + engine matching sendiri. AI writer-identification dan HTR Arab adalah fase riset 6-18 bulan SETELAH dataset terkumpul, berjalan batch di worker-ai â€” bukan fitur kuartal ini.

## Fase

### Fase 0 â€” Fondasi: skema data, auto-NIS, consent (software murni) — effort: sedang

(1) Migrasi: kolom baru di santri (nis_urut, nfc_uid, signature_path, signature_svg_path, consent), tabel santri_enrollment + handwriting_samples. (2) NisGeneratorService: template token per tenant via Setting (mis. {NSP}{TA:2}{URUT:4} ala Kemenag 18-digit atau {TA}.{URUT:4}), parser preg_replace_callback (JANGAN eval), counter race-safe MENIRU PERSIS SuratService (Modules/Core/app/Services/SuratService.php): lockForUpdate baris urut tertinggi + create dalam SATU transaksi, unique(tenant_id,nis) yang SUDAH ADA di migrasi santri sebagai backstop, retry sekali pada error 23505/23000. JANGAN tiru pola salah PpdbRegistrationNumberService (lock di transaksi terpisah = tidak melindungi apa pun). Derive urut dari kolom integer nis_urut, BUKAN parse MAX(nis) string. (3) Lembar persetujuan ortu/wali (UU PDP 27/2022: biometrik + data anak = data pribadi spesifik) yang eksplisit menyebut penggunaan sampel tulisan untuk AI internal, dicatat consented_at/consented_by; permission Spatie baru 'operate_stasiun' + pembatasan akses file enrollment.

Semua tulis lewat satu EnrollmentService (disiplin LoketKasâ†’PosKasService). TTD: szimek/signature_pad dibungkus sendiri sebagai komponen Livewire/Alpine Â±50 baris (JANGAN plugin Filament pihak ketiga â€” mayoritas masih v3/v4); simpan toSVG() sebagai master + PNG untuk IdCardService. ### Fase 2 â€” Pengumpulan sampel tulisan tangan berlabel (software + cetak formulir) — effort: sedang

FASE PALING BERNILAI â€” zero-AI tapi membangun dataset yang tak bisa dikejar belakangan. Formulir A4 ala protokol KHATT: Lembar A Arab (teks tetap mencakup 28 huruf semua posisi â€” mis. pangram Arab atau doa pendek pilihan ustadz, ditulis 2x + hijaiyah terisolasi + angka Ù -Ù©), Lembar B Indonesia (pangram Latin + alfabet lepas & sambung + angka), Lembar C opsional (paragraf bebas â€” paling bernilai untuk writer-ID text-independent). Fisik: kotak panduan PER BARIS (segmentasi otomatis kelak), marker sudut hitam (auto-deskew), QR chillerlan berisi NIS+kode_form+versi di pojok â†’ foto otomatis terasosiasi ke santri yang benar (salah label = fatal untuk dataset). Santri menulis SAAT ANTRI, di loket tinggal difoto (HP di stand + lampu, bukan webcam loket). Karena isi formulir DIKETAHUI, tiap baris otomatis punya ground-truth tanpa anotasi manual â€” simpan transkripsi per BARIS sejak awal (kompatibel PAGE XML/HTR-United). JPEG q0.9 setara 300dpi, JANGAN kompres agresif (goresan tipis = sinyal AI). QC di layar: blur/terpotong â†’ ulang foto. Baca QR via jsQR di browser.

**Prasyarat:** Fase 1 (pipeline kamera + halaman stasiun); keputusan owner: jumlah lembar per santri + teks Arab tetap; consent wali sudah ditandatangani (Fase 0); HP + stand + lampu Â±Rp150-300rb.

### Fase 3 â€” Kartu NFC: reader USB keyboard-wedge (hardware murah) — effort: kecil

Reader RFID/NFC 13.56MHz USB mode keyboard-emulation (~Rp100-250rb/loket di marketplace): tempel kartu â†’ UID terketik + Enter di input autofocus 'Tempelkan kartu...' di halaman stasiun â€” tanpa driver, jalan di PC & tablet Android via OTG. KRITIS saat beli: format output UID bervariasi antar firmware (desimal vs hex, byte-order terbalik) â€” beli 1 UNIT DULU untuk uji, lalu seragamkan model untuk semua loket; normalisasi UID ke hex lowercase tanpa pemisah sebelum simpan ke santri.nfc_uid. Keamanan jujur: UID MIFARE Classic mudah dikloning magic card (~Rp100rb-an) â€” UID-only CUKUP untuk identifikasi (absensi/panggil profil, foto santri tampil di layar petugas sebagai verifikasi visual), tapi transaksi UANG WAJIB UID + PIN (SantriAccountService â€” konsisten pelajaran modul Keuangan). QR NIS tetap dipertahankan sebagai fallback universal tanpa hardware. ACR122U (Rp420-650rb) hanya bila kelak mau MENULIS data bertanda tangan server ke kartu â€” bukan blocker peluncuran. WebNFC (NDEFReader) jalur kedua khusus bila stasiun memakai tablet Android ber-NFC.

**Prasyarat:** Fase 1 live; keputusan owner: model reader (beli 1 uji dulu) + stok kartu MIFARE; kolom nfc_uid dari Fase 0.

### Fase 4 â€” Passkey sidik jari via WebAuthn (HP pribadi, BUKAN tablet loket) — effort: sedang

Koreksi ekspektasi yang harus disampaikan ke owner: WebAuthn mengikat kredensial 1:1 ke perangkat â€” TIDAK BISA 'rekam jari di stasiun lalu login di mana saja'; Android hanya menampung 3-5 sidik jari per perangkat dan siapa pun yang terdaftar di tablet bersama bisa membuka credential SEMUA santri (anti-pattern shared-device). Yang realistis: di stasiun, petugas MEMANDU enrolmen passkey di HP PRIBADI santri/wali untuk login portal. Stack: asbiin/laravel-webauthn v6.0.0 (satu-satunya adapter matang yang eksplisit support Laravel 13, wrap web-auth/webauthn-lib ^5.3) + @simplewebauthn/browser. KRUSIAL multi-tenant: RP ID = pesantren.online (eTLD+1) agar credential berlaku lintas subdomain tenant; custom domain (asy-syifaa.com) butuh enrolmen terpisah. Tabel webauthn_credentials masuk DB per-tenant. Integrasikan sebagai metode baru di SantriLoginMethod (fingerprint saat ini siap=false). Langkah 'passkey' di checklist stasiun bertanda OPSIONAL â€” jangan jadi blocker alur. Scanner fingerprint USB (DigitalPersona 4500, Rp1,5-3jt): JANGAN BELI â€” butuh agent desktop per-PC Windows (gugur di Android) + engine matching 1:N sendiri (SourceAFIS) yang membebani VPS 8GB; proyek riset terpisah bila benar-benar dibutuhkan.

**Prasyarat:** Fase 1 live; keputusan owner menerima model 'passkey HP pribadi' sebagai pengganti 'fingerprint di loket'; SantriLoginMethod + portal login santri.

### Fase 5 â€” Riset AI: writer identification + HTR (SETELAH data terkumpul) — effort: besar

Dimulai 3-6 bulan setelah Fase 2 mengumpulkan sampel â‰¥50-100 santri; semua inference BATCH ASYNC malam via worker-ai (VPS 8GB CPU â€” puluhan detik-menit per gambar, JANGAN janjikan real-time). (a) WRITER-ID: preprocessing OpenCV (deskew via marker, crop, binarisasi) â†’ embedding CNN ~512-dim (adaptasi repo riset NetVLAD/DeepWriter; fallback awal fitur codebook klasik yang terbukti >91% dengan 1 halaman/penulis) â†’ simpan ke pgvector yang SUDAH terpasang, query cosine top-k; pisahkan embedding Arab vs Latin. Jujur: tidak ada model writer-ID pretrained plug-and-play â€” bagian ini engineering sendiri. (b) HTR: mulai dari Latin/Indonesia (microsoft/trocr-base-handwritten, kasus paling matang) sebagai bukti konsep; Arab via qwen2.5vl di Ollama + uji QARI-OCR v0.3 (akurasi pada tulisan ANAK belum terbukti model mana pun â€” evaluasi di 50 sampel sendiri); cloud fallback Azure Document Intelligence Read (~$1,50/1000 hal, resmi dukung handwriting Arab) untuk pembanding + bootstrap pseudo-label yang dikoreksi ustadz â€” HANYA jika owner setujui kebijakan privasi cloud. (c) Jangka 6-18 bln: fine-tune Kraken/eScriptorium (model Muharaf; ~10 halaman transkrip menurunkan error drastis, training di Colab/mesin lain) â†’ pipeline penilaian human-in-the-loop: scan lembar jawaban â†’ cabang identitas (embedding+pgvector, anti lembar tertukar) + cabang isi (HTR â†’ LLM banding kunci jawaban â†’ SARAN nilai + confidence) â†’ ustadz SELALU pemutus akhir, bukan auto-nilai.

**Prasyarat:** Dataset Fase 2 terkumpul (â‰¥50-100 santri, ground-truth per baris); infra pgvector+Ollama+worker-ai (SUDAH LIVE); keputusan owner soal cloud OCR; jangan ganggu RAM Ollama yang sudah dipakai modul AI Khadim.

## KEPUTUSAN OWNER (2026-06-11) — mengunci arah build

1. **Sidik jari ≠ passkey HP.** Dipakai untuk AKTIVITAS PONDOK: absensi & pembayaran di loket — kartu NFC mengidentifikasi, jari MEMVERIFIKASI (1:1 match terhadap template tersimpan), wajib/tidaknya per kebijakan pesantren. Konsekuensi: Fase 4 berubah → scanner fingerprint di loket + verifikasi server-side (SourceAFIS 1:1; agent kecil di PC loket karena browser tak bisa akses scanner USB) ATAU perangkat absensi standalone yang sync API. Simpan template di server per santri (fingerprint_template, terenkripsi).
2. **Format NIS: standar Kemenag/nasional** sebagai default — template `{NSP}{TA:2}{URUT:4}` bila NSP diisi, fallback `{TA}.{URUT:4}`; configurable per tenant.
3. **Persetujuan wali = Kebijakan Privasi Sistem Pondok** yang dipublikasikan (halaman publik tenant) dan DISETUJUI saat/sebelum daftar (checkbox di alur PPDB) — bukan lembar fisik per anak. Redaksi default disediakan platform, bisa diedit pesantren.
4. **OCR full LOKAL via VPS** (Ollama/worker-ai). Tidak pakai cloud.
5. **Sampel tulisan: 1-5 paragraf saja.** Tujuan UTAMA = HTR (sistem MEMBACA tulisan santri — Arab & Indonesia) untuk bantu penilaian; writer-identification = versi lanjut saat data sudah banyak. Ground-truth tetap per-baris (teks formulir diketahui).
