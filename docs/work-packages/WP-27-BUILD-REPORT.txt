================================================================================
DESIGN DECISIONS
================================================================================

1. Standalone KunjunganUks (not FK to RiwayatKesehatan)
   - Simpler schema, focused on visit flow
   - Can integrate later

2. Partial Unique: (tenant_id, santri_id, tanggal)
   - One santri per day max
   - Idempotent updateOrCreate allowed

3. Observer Pattern for auto-sync
   - Automatic, no explicit calls
   - Idempotent, auto-cleanup

4. Fire-and-forget notifications
   - Notif failures don't block response
   - Allows async processing

5. No Obat stock yet (WP-28 later)
   - Captures name only
